# Fabric-Aware Mesh Shape Enumeration

AutoParallel can search over many device mesh shapes before choosing a sharding
strategy. A naive mesh search enumerates arbitrary factorizations of
`world_size`, for example `(16, 8, 4)` for `512` GPUs. That is simple, but it can
create mesh dimensions that cross physical fabric boundaries. On a 64-node H100
cluster with 8 GPUs per node, `(16, 8, 4)` has a middle dimension that is partly
cross-node and partly node-local, so that dimension is a hybrid RDMA/NVLink
communicator.

Fabric-aware enumeration avoids those mixed-fabric dimensions. It first models
the global rank layout as fabric spans, then only cuts mesh dimensions inside a
single span. The result is a canonical list of mesh shapes whose axes are aligned
with physical communication tiers.

The implementation lives in `autoparallel.mesh_search`:

```python
from autoparallel.cost_models.nccl_cost_model import h100_topo_config
from autoparallel.mesh_search import (
    fabric_exponents_from_nccl_topo,
    generate_fabric_mesh_shapes,
)

topo = h100_topo_config(num_nodes=64, gpus_per_node=8)
fabric_exponents = fabric_exponents_from_nccl_topo(512, topo)
shapes = generate_fabric_mesh_shapes(512, fabric_exponents)
```

## Rank Layout Model

The current NCCL topology model exposes two communication tiers:

| Tier | Meaning |
|---|---|
| `rdma` | Cross-node communication |
| `nvlink` | Intra-node communication |

For a power-of-two world size, these tiers can be represented as a sequence of
rank-layout bit spans from outermost to innermost.

For `512` GPUs on `64` nodes with `8` GPUs per node:

```text
512 GPUs = 2^9
64 nodes = 2^6
8 GPUs/node = 2^3
```

So the fabric spans are:

```python
(("rdma", 6), ("nvlink", 3))
```

Equivalently:

```text
[ RDMA rank bits: 6 ][ NVLink rank bits: 3 ]
```

The rightmost bits are innermost and node-local. Mesh dimensions generated by
the fabric-aware enumerator are not allowed to consume bits from both spans.

## Step 1: Convert NCCL Topology to Fabric Exponents

`fabric_exponents_from_nccl_topo` converts an `NCCLTopoConfig` into the
outer-to-inner fabric spans:

```python
def fabric_exponents_from_nccl_topo(total_gpus, topo_config):
    total_exp = log2(total_gpus)
    intra_exp = min(total_exp, log2(topo_config.gpus_per_node))
    inter_exp = total_exp - intra_exp

    result = []
    if inter_exp:
        result.append(("rdma", inter_exp))
    if intra_exp:
        result.append(("nvlink", intra_exp))
    return tuple(result)
```

For H100 `512 = 64 x 8`, this returns:

```python
(("rdma", 6), ("nvlink", 3))
```

The helper validates that:

- `total_gpus` is a positive power of two.
- `gpus_per_node` is a positive power of two.
- `total_gpus <= num_nodes * gpus_per_node`.

If a future topology has more tiers, callers can bypass this helper and pass
explicit fabric spans directly to `generate_fabric_mesh_shapes`, for example:

```python
fabric_exponents = (("rdma", 4), ("nvl", 2), ("nvlink", 3))
```

## Step 2: Pick the DP Axis

`generate_fabric_mesh_shapes` treats mesh dimension 0 as the DP axis. The DP
axis is ordered and is carved only from the outermost fabric span.

For H100 WS512:

```python
fabric_exponents = (("rdma", 6), ("nvlink", 3))
```

The enumerator tries:

```text
dp_exp = 0, 1, 2, 3, 4, 5, 6
```

where:

```text
dp_size = 2^dp_exp
```

If `include_dp_axis_when_one=True`, `dp_exp=0` still produces an explicit
leading `1`, such as `(1, 64, 8)`. If it is `False`, that leading size-1 axis is
omitted.

After choosing `dp_exp`, the remaining fabric spans are searched recursively. For
example, with `dp_exp=4`:

```text
DP dim: 2^4 = 16
RDMA remaining: 6 - 4 = 2 bits
NVLink remaining: 3 bits
```

The remaining mesh dimensions must be formed from `RDMA=2` and `NVLink=3`
separately.

## Step 3: Partition Each Fabric Independently

Each remaining fabric span is split into one or more mesh dimensions by
partitioning its exponent.

For example, `nvlink_exp = 3` can be partitioned as:

| Exponent partition | Mesh sizes |
|---|---|
| `(3,)` | `(8,)` |
| `(1, 2)` | `(2, 4)` |
| `(1, 1, 1)` | `(2, 2, 2)` |

The partition is over exponents, not sizes. Each exponent `e` becomes a mesh
dimension of size `2^e`.

Each fabric is partitioned independently. The enumerator never creates one mesh
dimension by combining leftover RDMA bits with NVLink bits.

## Canonicalization

Within a single non-DP fabric, dimensions are canonicalized by using
nondecreasing exponent partitions.

This removes duplicates that differ only by swapping dimensions inside the same
fabric:

```text
kept:    exponents (1, 2) -> sizes (2, 4)
removed: exponents (2, 1) -> sizes (4, 2)
```

The ordering between different fabric spans is still meaningful and is preserved:

```text
RDMA dimensions come before NVLink dimensions.
```

The DP axis is also ordered and is not canonicalized against the other RDMA
dimensions. This means `(2, 4, 16, 8)` and `(4, 2, 16, 8)` can both be meaningful
if the first dimension is DP in one shape but not in the other.

## Why `(16, 4, 8)` Is Generated but `(16, 8, 4)` Is Not

Use H100 WS512 again:

```python
fabric_exponents = (("rdma", 6), ("nvlink", 3))
```

Choose:

```text
dp_exp = 4
```

That gives:

```text
dim0 = 2^4 = 16
RDMA remaining = 2 bits
NVLink remaining = 3 bits
```

A fabric-aligned shape is:

```text
RDMA remaining:   (2) -> 4
NVLink remaining: (3) -> 8
shape: (16, 4, 8)
```

But `(16, 8, 4)` would require:

```text
shape exponents: (4, 3, 2)
```

After `dim0=16` consumes 4 RDMA bits, only 2 RDMA bits remain. The next
dimension, `8 = 2^3`, would need 3 bits, so it would consume:

```text
2 RDMA bits + 1 NVLink bit
```

That mesh dimension crosses the RDMA/NVLink boundary. Fabric-aware canonical
enumeration intentionally excludes it.

## WS512 H100 Example

For:

```python
topo = h100_topo_config(num_nodes=64, gpus_per_node=8)
fabric_exponents = fabric_exponents_from_nccl_topo(512, topo)
shapes = generate_fabric_mesh_shapes(512, fabric_exponents)
```

the fabric exponents are:

```python
(("rdma", 6), ("nvlink", 3))
```

With the default `max_ndim=4`, the enumerator returns 24 shapes:

```text
(64, 8)
(1, 64, 8)
(2, 32, 8)
(4, 16, 8)
(8, 8, 8)
(16, 4, 8)
(32, 2, 8)
(64, 2, 4)
(1, 2, 32, 8)
(1, 4, 16, 8)
(1, 8, 8, 8)
(1, 64, 2, 4)
(2, 2, 16, 8)
(2, 4, 8, 8)
(2, 32, 2, 4)
(4, 2, 8, 8)
(4, 4, 4, 8)
(4, 16, 2, 4)
(8, 2, 4, 8)
(8, 8, 2, 4)
(16, 2, 2, 8)
(16, 4, 2, 4)
(32, 2, 2, 4)
(64, 2, 2, 2)
```

The list is sorted by:

```python
key=lambda shape: (len(shape), shape)
```

so lower-rank meshes appear first, followed by lexicographic order.

## Parameters

### `max_ndim`

Controls the maximum number of mesh dimensions.

```python
generate_fabric_mesh_shapes(512, fabric_exponents, max_ndim=4)
```

This limits solver search to at most 4D meshes. Smaller values reduce candidate
count and solver cost. Larger values allow more fine-grained fabric splits.

### `include_dp_axis_when_one`

Controls whether `dp_exp=0` creates an explicit leading size-1 DP axis.

```python
generate_fabric_mesh_shapes(
    512,
    fabric_exponents,
    include_dp_axis_when_one=True,
)
```

With `True`, shapes such as `(1, 64, 8)` can appear. With `False`, the same
logical split would appear as `(64, 8)`.

## Relationship to the Cost Model

Fabric-aware enumeration is a candidate-generation policy. It does not replace
the NCCL cost model.

The NCCL cost model can still score hybrid shapes such as `(16, 8, 4)` by
deriving each mesh dimension's effective topology. Fabric-aware enumeration
simply chooses not to generate those hybrid shapes when the search should be
restricted to clean fabric-aligned axes.

This separation is useful:

- Use fabric-aware canonical enumeration when searching a compact, topology-clean
  candidate set.
- Use broader ordered factorization if you intentionally want to compare hybrid
  mesh dimensions against fabric-aligned alternatives.

## Summary

Fabric-aware canonical enumeration works in exponent space:

1. Convert topology to outer-to-inner fabric spans, such as
   `(("rdma", 6), ("nvlink", 3))`.
2. Pick an ordered DP exponent from the outermost span.
3. Partition each remaining fabric span independently.
4. Canonicalize dimensions within each non-DP fabric by using nondecreasing
   exponent partitions.
5. Convert exponents back to mesh sizes with `size = 2^exp`.

The key invariant is that every generated mesh dimension is fully contained
inside one fabric span. That is what keeps generated shapes topology-aligned and
avoids RDMA/NVLink hybrid dimensions.
